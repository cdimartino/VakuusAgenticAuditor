# Encounter option accounting — Steam 26660232

**Ready for exact-build static accounting. Not a certification of playthroughs or a complete encounter simulator.** Every in-scope catalog/model identity below has a disposition. A deferred row is an intentional limit, not a zero score or an assertion that the choice is unreachable.

Rows at different levels overlap by design: an event, its option, and the relic the option can show are not three distinct offers. `fields` lists exact suffixes on option stems, so absent fields are visible and changes are checked. For example, the two `HUNGRY_FOR_MUSHROOMS` options have title keys but use relic descriptions through `EventOption.FromRelic`; `DOLL_ROOM.pages.TAKE.options.TAKE` has a description key but builds buttons from the selected relic; `THE_LANTERN_KEY.pages.DONE.options.RETURN_THE_KEY` is description-only and is passed to `SetEventFinished`, not offered as a second return choice. Narrative pages are not separate options. A `LOCKED` page name alone is not proof of a locked button: `MUSEUM_OF_TORTURE.pages.LOCKED.options.CONTINUE` advances to the display. `TRIAL.pages.REJECT.options.DOUBLE_DOWN` is flagged `IsProceed`; `DoubleDown` opens the game's abandon-run confirmation.

## How to read dispositions

- **`modeled`**: the visible local effect has a direct heuristic in `mod/EventEffects.cs`, mainly displayed HP/gold changes and the explicit Sword of Stone rule. This describes local comparison, not a game callback or a future-state simulation.
- **`conditional_live`**: the mod needs the current enabled offer, legal targets or actual visible identities, or it covers only part of the effect. For ordinary events, the reason distinguishes card fit, upgrades, recurrent HP costs, a random reward plus a known cost, and other gaps. Potion Courier uses its dedicated belt/reward rule. Spirit Grafter's heal and upgrade cost are separate from Metamorphosis's uncertain combat outcome. A visible fight or next page is not an expected-value estimate.
- **`deferred`**: no trustworthy dedicated comparison for the stated effect or family. This includes random reward sets and relic exchanges, crafting, Crystal Sphere's board, most camp actions, mode-only choice valuation, and future encounter branches. A generic prompt is not a specialized model.
- **`not_ranked`**: control/metadata, test-only, deprecated, unavailable or terminal. `availability` records why; labels describe the audit decision, not a guarantee that every game control takes the same UI path.

Event assessment starts at visible, enabled, current-page `NEventOptionButton` entries in `mod/Entry.cs`, excluding locked/proceed buttons and completed offers. It uses `EventEffects`, `EventCoach`, `AncientOffer` and `NonupeipeBlessing` rather than executing callbacks. `encounter-event-policy.tsv` explicitly assigns a reason to every shipped event option stem: no default assigns an unexplained new option to coverage. Other room mappings come from `Entry.Battle`, `Entry.Camp`, `Entry.Shop`, `Entry.Selection`, the treasure and rewards branches, `RouteCoach`, `mod/catalogs/26660232/bosses.tsv`, and [enemy intent coverage](enemy-knowledge.md). Generic card/relic heuristics are not taken as proof that actual options were seen.

## Dynamic boundaries and evidence

- Wellspring's `Bottle` samples an unlocked potion; the coach reads available slots and Sozu without rolling that reward. `Bathe` opens a one-card removal picker and adds the displayed number of Guilty cards. A newly acquired Guilty is unplayable and removes itself after five combats. `WellspringCoach` compares these costs against the removable deck instead of treating a random potion as an unknowable choice.
- Inspect `get_AllPossibleOptions` and `GenerateInitialOptions` on the eight Ancient pool models. `tools/encounter_audit` reads CIL metadata operands in their pool methods without loading game code. Per-owner relic ID counts: Darv 12, Neow 30, Nonupeipe 10, Orobas 10, Pael 10, Tanx 10, Tezcatara 10, Vakuu 10. Neow's positive and curse pools, and its six special option builders, are counted once per identity. Ancient pools apply `AllowedOptions`, subclasses can replace/filter candidates, and generated relics can attach live character/card payloads. The ledger uses one base ID for Orobas's `SEA_GLASS` character variants and Darv's `DUSTY_TOME` card variants; it does not model their distributions or enumerate every possible materialized instance. [Ancient gift notes](ancient-gifts.md) describe scoped Darv/Nonupeipe comparisons.
- `EventModel.RelicOption` constructs `ROOT.pages.PAGE.options.RELIC_ID`; `EventOption.FromRelic` uses the event fields if present, otherwise the relic title and `DynamicEventDescription`. `DollRoom.OptionFromChoice` instead builds a button from the relic title; its three candidates are read from `.cctor`. `FakeMerchant` has no localized event options: `.cctor` defines fake inventory relics and the Foul Potion callback has a separate relic result. Museum display candidates come from `MuseumOfTorture.CalculateVars`. `ThermaeNonupeipe.CalculateVars` samples a filtered Nonupeipe offer; the generated gift is a runtime family. Other swaps, random rewards, shop stock, legal targets and selected-card instances remain runtime-dependent.
- `Neow.GenerateNeowModifiers` delegates to the run's modifiers; the five assembly models overriding `GenerateNeowOption` are separate IDs. `Neow.GenerateInitialOptions` has a separate Blitz branch using `BLITZ.NEOW`; Blitz Merchant choices are accounted for under their own catalog stems. These are not standard-run options. Duplicate or co-op/mode interactions, late pages and follow-up GUI flows have not been exhaustively exercised.
- `mod/Entry.cs` gates combat advice on live player-turn state and available intents; the per-encounter rows identify paths, not solved enemy scripts. Meaningful next evidence would be live captures of unusual rest actions, generated Ancient/card and relic choices in their actual selection screens, alternate modes and co-op decision flows, plus targeted combat cases with hidden intent and phase changes. The static release gate cannot substitute for that evidence.

## Reproduce the owned-data gate

Use Python 3 and the .NET 9 SDK, with the audited macOS arm64 game install (or its archived PCK, adjacent `release_info.json`, and exact `sts2.dll`):

```sh
python3 tools/audit_encounter_options.py "/path/to/Slay the Spire 2.pck" --check
```

For an archived layout, use `--assembly "/path/to/sts2.dll"` and optionally `--steam-manifest "/path/to/appmanifest_2868840.acf"`. The local install was checked against Steam app `2868840`, build `26660232`, release `v0.113.1` / `d09d48e5` / `-1414792094`. The assembly SHA-256 is `a671e9efb86a7b80405133105665867b053c787670d475b4347cf5ccc15cb5fb`, MVID `1a667627-d2cf-4b1d-ade2-39da43f6f1f0`; REA metadata identity `ev_290d27a1738c0066781ee46939da72faedbc93476db73d296498d5307e6456c3`. Behavior claims above come from selected installed CIL methods and repo source; nothing was played or invoked.

The gate uses `tools/catalog.py` and `inventory.tsv`, validates explicit event/Ancient dispositions and compares all expected rows against the committed ledger, including option field shape and digest. Missing, extra, duplicate, unknown or changed rows fail. Catalog-backed digests hash the sorted field/value map; assembly-based rows cite the pinned assembly digest. No localized values or assets are emitted. `--write` regenerates a reviewed ledger but does not invent event/Ancient policy for unknown IDs. On a later build, review eligibility and any new builders or data sources rather than just changing the identity check.
